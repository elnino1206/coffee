## 2. Решения и почему

Чтобы следующий агент не переигрывал уже принятое.

**Скидка фиксируется числом в записи.** `discount_percent` пишется при
оформлении из `config('subscription.default_discount_percent')`. Правка
настройки не меняет условия тем, кто подписался раньше. На это есть тест
`test_discount_is_frozen_at_signup`.

**У неактивной подписки нет даты отгрузки.** `pause()`, `cancel()` и
состояния фабрики обнуляют `next_delivery_at`, а `nextDeliveryLabel()`
отдаёт `null` для всего, кроме активной. Сохранённая дата в строке
читалась бы как обещание привезти кофе.

**Возобновление отсчитывает цикл заново от сегодня.** Продолжать с
отложенной даты нельзя — она давно прошла, и подписка отгрузилась бы
немедленно.

**Пауза и блокировка разведены.** Паузу ставит и снимает покупатель;
блокировку ставят три неудачных списания, снимает удачная оплата.
Покупатель заблокированную возобновить не может, но **отменить может** —
он вправе прекратить попытки списания, не дожидаясь, пока карта
заработает.

**Отменённая подписка остаётся записью.** По ТЗ 5.2 при отмене
показывается удерживающее предложение, а в кабинете видна история.
Отменённые уходят вниз списка, но не исчезают.

**Причина отмены необязательна.** Требовать объяснение на выходе — способ
удержать силой, а не доводом.

**Раздел админки только показывает.** Кнопка правки означала бы, что
менеджер может остановить чужую подписку молча. Паузу ставит покупатель,
блокировку — списания.

**Вариант товара `nullOnDelete`.** Товар может уйти из продажи, подписка
остаётся: менеджеру нужно видеть, кому перестало приезжать. Везде, где
показывается позиция, есть ветка на `null`, а `chargeTotal()` возвращает
`null`, а не ноль — это разные вещи.

**Первая отгрузка через `frequency_weeks` от оформления.** Когда подключат
списания, первая уйдёт вместе с первым платежом, и эта дата станет датой
второй. Отмечено комментарием в `PlaceSubscription`.

## 4. Окружение

### Что изменено на машине

Контейнеров не было ни одного, а `.env` смотрит на PostgreSQL по порту
5434. Поднят контейнер (пароль подставить из `DB_PASSWORD` в `.env`,
в этом файле он намеренно не записан):

```bash
docker run -d --name aljar-pg -e POSTGRES_USER=aljar -e POSTGRES_PASSWORD="$DB_PASSWORD" -e POSTGRES_DB=aljar -p 5434:5432 -v aljar-pgdata:/var/lib/postgresql/data postgres:17-alpine
```

Дополнительно создана база `aljar_test` — её ждёт `phpunit.xml`:

```bash
docker exec aljar-pg psql -U aljar -d aljar -c "CREATE DATABASE aljar_test OWNER aljar"
```

Миграции накатаны, посеяны `CatalogSeeder`, `AdminSeeder` и
`SubscriptionSeeder`. В базе пять подписок: SUB-100 и SUB-101 активные,
SUB-102 на паузе, SUB-103 заблокирована (`failed_charge_count = 3`),
SUB-104 отменена.

### Почему не собирается фронтенд

`node_modules` установлен под Linux. Внутри `@rolldown/binding-linux-x64-gnu`
и `-musl`, Windows-бинарника `@rolldown/binding-win32-x64-msvc` нет;
у `unrs-resolver` то же самое. Windows-шимов `.cmd` в `node_modules/.bin`
тоже нет, поэтому `npm run` не находит бинарники.

**Для агента на Linux это значит, что делать ничего не нужно** — текущий
`node_modules` как раз под вашу платформу, сборка должна пойти сразу.
Переустановка (`npm install`) требуется только на Windows.

### PHP

В `PATH` на Windows-машине лежит PHP 8.2.11, а проект требует ≥ 8.4.1.
Рабочий бинарник там: `~/.config/herd/bin/php84/php.exe`. На Linux —
обычный `php` нужной версии, оговорка неактуальна.

## 7. Чего в подписках нет

Списаний. Платёжный контур Т-Банка не подключён, таблицы `payments` не
существует. Поэтому подписка **не порождает заказы сама и не снимает
деньги** — сейчас это запись, с которой работают кабинет и панель.

Схема под это готова: `failed_charge_count`, `blocked_at`, статус
`Blocked`. По доменной модели (раздел 6) правило такое: три попытки, по
одной в сутки, после третьей блокировка; счётчик обнуляется удачным
списанием; каждая неудача — письмо покупателю. Каждая отгрузка должна
порождать обычный `Order` со ссылкой на подписку, иначе повтор в один
клик из кабинета (ТЗ 5.3) не увидит регулярные покупки.

Уведомлений по подписке тоже нет: по доменной модели нужны письма
покупателю на отгрузку и на неудачное списание.
